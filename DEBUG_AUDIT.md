Проверены Swift-код приложения, пути импорта и хранения данных, категоризация,
AI-чат, цели, геймификация, финансовые инструменты, Firebase-батлы и оба proxy.

## Повторяемая проверка

Из корня проекта:

```sh
bash Tests/run-checks.sh
```

Это четыре Swift-проверки и 44 Node-теста. Они используют память и временные
каталоги, не меняют пользовательскую базу, не запускают приложение и не делают
реальные AI-запросы. PDF-проверка читает проектный файл и выводит только число строк.
URLProtocol проверяет лимиты, частичный успех и отмену запросов без реального HTTP.
Проверена сборка Debug для iOS Simulator без подписи. Предупреждения о старых
deployment target и build scripts остаются в сторонних Pods.

Серверные исправления развёрнуты в Firebase (`openrouterProxy`, проект
`finlit-9b600`). Живая проверка: `/health` вернул HTTP 200; запрос категоризации
с нулевой суммой — HTTP 400 и понятную ошибку до обращения к AI.

## Ограничения проверки

- Реальную синхронизацию двух iPhone, работу в офлайне с возвратом связи,
  клавиатуру, производительность первого запуска и доставку уведомлений нужно
  проверить на устройствах. Модель обновления участников проверена локально;
  живые пользовательские комнаты для тестов не менялись.
- Правила доступа Firestore и настройки App Check в облачной консоли здесь не
  проверялись. HTTP proxy пока не проверяет Firebase Auth/App Check — это
  отдельная задача перед публичным распространением приложения.
- В git отслеживается `FinLit/gold_statement.pdf`. Следует убедиться, что это
  обезличенный пример, прежде чем публиковать репозиторий. Файл не удалялся.
- Старые сохранённые операции не перезаписываются автоматически. Исправленный
  парсер не может сам восстановить записи, ранее потерянные при импорте; для
  восстановления требуется исходная выписка и отдельная сверка с ручными правками.
- Произвольные неоднозначные вопросы естественным языком не гарантируют точного
  распознавания периода. Кнопки человека/категории/месяца используют точные локальные фильтры.
